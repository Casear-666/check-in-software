# CLAUDE.md - 精力感知日历项目开发规范

## 🎯 项目概述
本项目是一个基于 React + React Big Calendar + MySQL 的全栈任务管理日历应用。核心特性为"动态重叠可视化"与"完整 CRUD 交互"。所有开发工作必须严格遵循以下架构与性能约束。

## ⚠️ 核心性能红线（最高优先级）
- **拖拽过程零网络请求**：拖拽/拉伸过程中的重叠颜色计算、幽灵位置渲染必须是纯前端内存计算。严禁在拖拽过程中调用后端接口查询重叠数或同步数据。
- **仅在松手时持久化**：所有数据同步操作仅在 `onDrop` / `onResizeStop` 回调触发时执行。
- **乐观更新**：前端松手后立即更新 UI 状态，异步发送请求。后端返回失败时回滚 UI 并提示用户，保证体感零延迟。
- **防抖合并**：前端对拖拽产生的更新请求加 300ms 防抖队列，合并短时间内的多次请求，防止请求风暴。

## 🎨 前端功能规范

### 1. 动态渐变重叠着色系统
- 废除固定三色映射，实现根据重叠数量 N 动态计算颜色的算法。
- 色阶采用绿→黄→橙→红的连续色谱过渡，支持任意重叠数量映射，相邻色块可加入轻微渐变提升质感。
- 拖拽/拉伸时必须实时计算并渲染幽灵位置的重叠颜色。

### 2. 任务编辑与交互
- 完整 CRUD：点击空白处创建、双击弹窗编辑（标题/描述等）、删除功能。
- 拖拽交互：支持自由拖拽移动（改时间）和边缘拉伸（改时长）。
- 所有操作必须有即时 UI 反馈，交互流畅无卡顿。

## 🗄️ 后端与数据库规范

### 1. 数据库设计
- 任务表必须包含 id, title, start_time, end_time, description 字段。
- `start_time` 和 `end_time` 必须建立联合索引，支撑重叠校验与时间段查询。

### 2. API 设计
- 提供精准的 `PATCH /api/tasks/:id/time` 接口，仅接收 `{start, end}` 字段，禁止全量更新。
- 所有前端操作（创建/编辑/删除/拖拽调整）必须真实持久化到 MySQL，刷新后数据完全一致。

## 📦 交付与代码规范
- 开发顺序：先完成前端视觉与交互闭环，再搭建后端 API 与数据库连接。
- 拖拽变色核心算法需保证性能，避免重渲染导致的卡顿。
- 代码结构清晰，关键逻辑添加注释，便于后续维护。
